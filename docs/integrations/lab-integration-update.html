Lab Integration Update

Where the Vyara ⇄ MI Partner lab integration stands: the approach settled on zero changes on the Salesforce side, both booking paths built, and reception booking going live first.

Build complete · pending go-live Date 2026-08-21 From Vyara Engineering
In brief

The headline

Approach

Zero Salesforce dev. Vyara books through the lab’s existing endpoints; the lab builds nothing new.

Live first

Reception booking (option 1). Reception books each prescribed test at sign time.

Staged

Patient self-booking (option 2). Built and behind a flag — switch on later, no rebuild.

How we got here

Decision log

Three decisions shaped the final design. The order matters — each one narrowed the build.

  1. Starting point

    Approach 1 — prescription-notify

    Vyara would notify the lab the moment a test is prescribed, and the lab’s team would book the slot. This needed one new endpoint on the lab side: a notify that accepts an order with no appointment time.

  2. Constraint

    The lab won’t develop anything → pivot to zero-change

    Since the Salesforce team is not keen to build, we removed the only thing that required their effort. Vyara now sources a slot from the lab’s existing getAvailableSlots and books via their existing bookFullAppointment / EnquiryCenterAppointment. The lab’s only role is collecting the sample and posting the status webhooks it already sends.

  3. Rollout

    Reception first, patient portal staged

    Both booking paths were built. Reception booking (option 1) goes live now. Patient self-booking (option 2) is complete but gated behind a feature flag so it can be turned on later without any further development.

To go live

Next steps

Two owners. Once these are done, option 1 is live; option 2 is a single flag away.

VYARA

Apply the database changes to UAT (a one-time additive migration) and load the lab credentials into the environment, then switch the integration on.

MI PARTNER

Confirm we may use the existing endpoints, share the exact getAvailableSlots response shape, rotate the leaked UAT credentials, and confirm the webhook authentication method.

THEN

Go live with reception booking. When ready, enable patient self-booking by flipping one flag — no further development.
